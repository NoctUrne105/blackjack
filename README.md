# 命运二十一：地牢契约

一个单文件可运行的 21 点 Roguelike 牌桌战斗原型。玩家在地牢路线中通过战斗、事件、商店和篝火逐步构筑技能与遗物，最终挑战 Boss「无脸荷官」。

## 运行方式

直接打开仓库中的 `blackjack_roguelike_demo.html` 即可游玩，不需要安装依赖或启动服务器。

也可以下载该文件后用浏览器打开：

```text
blackjack_roguelike_demo.html
```

## 核心玩法

- 每场战斗由多个牌局组成，双方按 21 点规则抽牌。
- 玩家可以选择要牌、停牌、窥牌、翻倍，或消耗能量使用技能。
- 点数越接近 21，停牌结算时造成的伤害越高。
- 超过 21 会爆牌，并受到契约反噬。
- 敌人会根据不同性格决定是否跟牌、停牌或触发特殊行为。
- 战斗胜利后可以获得金币、技能、遗物或属性奖励。

## 当前内容

- 3 个初始角色：赌徒、作弊师、守誓骑士
- 多种敌人类型：普通敌人、精英敌人、最终 Boss
- 地牢路线：战斗、事件、精英、商店、篝火、Boss
- 构筑系统：技能、遗物、金币、诅咒、生命上限
- 战斗反馈：敌人意图、牌局日志、点数提示、局末统计

## 操作说明

- **要牌**：抽一张牌，敌人可能跟牌。
- **停牌结算**：按当前点数造成伤害并进入敌方反击。
- **窥牌**：消耗能量查看下一张牌。
- **翻倍**：强制再抽一张牌，本局停牌伤害翻倍。
- **技能**：消耗能量改变点数、获得护盾、造成伤害或控制牌堆。

## 设计目标

这个原型的重点不是复刻传统 21 点，而是验证一个核心体验：

> 玩家能否通过技能、遗物和风险判断，把随机抽牌变成可规划的战斗构筑。

因此，游戏鼓励玩家在「继续抽牌争取高收益」和「及时停牌避免爆牌」之间反复权衡。

## 设计起因与目的

本项目的灵感主要来源于 `Slay the Spire` 和 `Balatro`。`Slay the Spire` 提供了清晰的「路线推进 - 战斗 - 奖励 - 构筑」循环参考；`Balatro` 则展示了如何把玩家熟悉的传统牌类规则重新包装成具有成长、倍率、组合和风险收益判断的策略体验。

在这个基础上，我希望尝试把传统 21 点中最核心的心理张力，也就是「是否继续抽下一张牌」转化为一个可扩展的战斗系统。传统 21 点的规则简单、反馈直接，玩家每次决策都能感受到风险和收益的变化；而 Roguelike 的构筑、随机奖励和路线推进，天然适合放大这种风险判断。

因此，项目的设计目的不是单纯做一个 21 点小游戏，而是验证一种玩法方向：能否用低理解成本的牌局规则，承载角色差异、技能组合、遗物构筑、敌人机制和 Boss 规则。希望玩家即使第一次进入游戏，也能快速理解「接近 21 点更强，但爆牌会受罚」这一核心逻辑，并在后续通过技能和遗物逐渐形成自己的打法。

从游戏策划角度看，这个 Demo 主要用于验证三个问题：

- 21 点规则是否能支撑回合制战斗的核心循环。
- 随机抽牌带来的不确定性，能否通过技能、遗物和敌人意图转化为可规划的策略。
- 一个短流程原型是否能完整呈现 Roguelike 的「战斗 - 奖励 - 构筑 - 再挑战」体验。

## 过程中的思考

设计过程中首先考虑的是如何避免玩法停留在「比大小」或「纯运气抽牌」。如果玩家只能一直抽牌或停牌，决策空间会很快变窄。因此，战斗系统加入了能量、技能、护盾、诅咒、翻倍和遗物，让玩家可以主动改变风险。例如窥牌可以提前获得信息，折算可以降低爆牌风险，守势可以把失败代价压低，翻倍则让玩家用更高风险换取更高收益。

其次，敌人不能只是生命值不同，否则每场战斗的体验会重复。所以敌人设计成不同的行为倾向：有的敌人激进抽牌，有的敌人保守停牌，有的敌人惩罚窥牌，有的敌人反制翻倍。这样玩家面对不同敌人时，需要调整自己的出牌和技能使用节奏。

最后，Roguelike 的构筑感来自「选择会影响后续局势」。因此奖励不只提供数值成长，也提供规则变化。遗物和技能会改变玩家看待牌局的方式，例如爆牌可以转化为反伤，正好 21 点可以带来额外资源，商店价格也可以被遗物影响。这样玩家每次选择都不只是当下变强，而是在改变之后几场战斗的策略路径。

## 遇到的困难与设想的解决方案

**困难一：随机性过强，玩家容易觉得输赢不可控。**  
设想的解决方案是增加更多信息获取和风险修正手段，例如窥牌、烧牌、折算、爆牌保护和敌人意图提示。这样抽牌仍然保留随机性，但玩家可以通过资源消耗和构筑选择主动管理风险。

**困难二：21 点规则本身较短，容易缺少长期成长目标。**  
设想的解决方案是用 Roguelike 结构拉长体验：通过战斗奖励、事件、商店、篝火和 Boss 节点，让玩家在一局流程中不断获得新工具。每个新技能或遗物都应改变玩家对「要不要继续抽牌」的判断，而不是只增加伤害数值。

**困难三：敌人差异如果只体现在数值上，战斗会重复。**  
设想的解决方案是为敌人设计不同的规则压力。例如反窥牌敌人限制信息优势，反翻倍敌人限制爆发打法，Boss 隐藏暗牌制造不完全信息。通过规则差异，而不是单纯提高生命或伤害，增加战斗辨识度。

**困难四：界面需要同时展示牌面、点数、生命、能量、敌人意图和日志，信息容易拥挤。**  
设想的解决方案是把界面分为牌桌区和信息区：牌桌区专注展示双方手牌与主要操作，侧边栏展示牌局状态、遗物和日志。这样玩家可以优先关注当前决策，同时保留复盘信息。

**困难五：单文件原型不利于后续扩展。**  
当前版本为了快速验证玩法，采用了单 HTML 文件实现。后续如果继续开发，可以将角色、敌人、技能、遗物和事件拆成独立数据配置，再把战斗结算逻辑、界面渲染和地图流程分离，方便平衡调整与内容扩充。
